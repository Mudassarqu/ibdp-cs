CPU Architecture — Component Relationships
📖 IB Definition — Arithmetic Logic Unit (ALU)
The Arithmetic Logic Unit (ALU) is the component of the CPU that performs all arithmetic operations (such as addition, subtraction, multiplication and division) and all logical operations (such as AND, OR, NOT and comparisons) on data. The ALU receives operands from registers, executes the operation directed by the Control Unit, and stores the result in the Accumulator.
What the ALU Does
ArithmeticAddition (+), Subtraction (−), Multiplication (×), Division (÷) on binary numbers
LogicalAND, OR, NOT, XOR — compares values, checks conditions (e.g. is A > B?)
ResultEvery operation's result is sent to the Accumulator (AC) for temporary storage
ControlThe ALU does not decide what to do — it receives instructions from the Control Unit
Why the ALU Matters
Every appEvery application — from a calculator to a game to a browser — relies on ALU operations
SpeedModern ALUs can perform billions of operations per second, driven by the CPU clock
Exam tipIf asked to "outline" ALU: state it performs arithmetic AND logical operations + give example
✏️ Exam Short Note — If asked "Describe the function of the ALU"
The ALU (Arithmetic Logic Unit) is the component of the CPU responsible for performing all arithmetic operations such as addition and subtraction, and all logical operations such as AND, OR and NOT. The results of these operations are stored in the accumulator. The ALU receives operands from registers and is directed by the Control Unit.
📖 IB Definition — Control Unit (CU)
The Control Unit (CU) is the component of the CPU that coordinates and controls all activities of the processor and the flow of data between the CPU and other hardware. It fetches instructions from memory, decodes them to determine what action is required, and then issues control signals to the appropriate components to execute the instruction. It manages the Fetch–Decode–Execute cycle.
CU Responsibilities
FetchDirects the PC to send the next instruction's address to MAR, then retrieves instruction into IR
DecodeInterprets the binary instruction in the IR — identifies the operation and operands needed
ExecuteSends control signals to the ALU, registers, or memory to carry out the instruction
Control BusAll CU signals travel via the Control Bus to reach ALU, registers and memory
CU Analogy & Key Facts
AnalogyThe CU is like an orchestra conductor — it does not play music itself, but directs every musician
ClockAll CU operations are synchronised with the system clock — faster clock = more cycles/second
Exam tipCU questions often use "Outline the role of the CU" — say: coordinates, controls, fetches, decodes, executes
✏️ Exam Short Note — If asked "Outline the role of the Control Unit"
The Control Unit (CU) is responsible for coordinating all operations within the CPU. It manages the Fetch–Decode–Execute cycle by fetching instructions from memory into the Instruction Register, decoding the instruction to determine what operation is required, and sending control signals to the appropriate components (such as the ALU or memory) to execute the instruction. The CU does not process data itself — it directs all other components.
📖 IB Definition — Registers
Registers are small, extremely fast storage locations located directly within the CPU. They hold data, instructions, and addresses that are currently being used or processed by the CPU. Because registers are inside the CPU chip itself, accessing them is orders of magnitude faster than accessing RAM. There are five key registers in the IB syllabus: PC, IR, MAR, MDR, and AC.
PC
Program Counter
Holds the memory address of the next instruction to be fetched from RAM. After each fetch, the PC is automatically incremented (+1) to point to the following instruction, ensuring sequential execution unless a jump/branch instruction changes it.
Exam answer: "The PC holds the address of the next instruction to be executed; it is incremented after each fetch to point to the subsequent instruction."
IR
Instruction Register
Holds the current instruction being decoded and executed. Once an instruction is fetched from memory via the MDR, it is loaded into the IR where the Control Unit reads and interprets it to determine what operation to perform.
Exam answer: "The IR holds the instruction that is currently being decoded by the Control Unit; it temporarily stores the instruction fetched from memory."
MAR
Memory Address Register
Holds the memory address to be accessed — either for reading an instruction or reading/writing data. The MAR is connected to the address bus; whatever address is in the MAR is sent to RAM to specify which memory location to access.
Exam answer: "The MAR holds the address in memory that the CPU needs to access; this address is sent along the address bus to RAM."
MDR
Memory Data Register
Holds the data that has just been read from memory, or the data that is about to be written to memory. It acts as a buffer between the CPU and RAM. During a fetch, the instruction from RAM arrives in the MDR before being transferred to the IR.
Exam answer: "The MDR temporarily stores data that has been read from or is to be written to memory; it acts as an interface between the CPU and RAM."
AC
Accumulator
Holds the result of the most recent arithmetic or logical operation performed by the ALU. It serves as a temporary storage area for intermediate results, reducing the need to repeatedly write results back to slower RAM during a sequence of calculations.
Exam answer: "The accumulator stores intermediate arithmetic and logic results; it reduces the number of memory accesses by holding results within the CPU."
✏️ Exam Short Note — If asked "State the difference between MAR and MDR"
The MAR (Memory Address Register) holds the address in memory that the CPU wishes to access, and is connected to the address bus. The MDR (Memory Data Register) holds the actual data that was read from or is to be written to that address, and is connected to the data bus. The MAR specifies WHERE; the MDR holds WHAT.
📖 IB Definition — System Buses
Buses are sets of parallel electrical conductors (wires) that transfer data between the CPU, memory, and input/output devices. There are three distinct system buses: the Address Bus, the Data Bus, and the Control Bus. The width of a bus (number of parallel lines) determines how much data can be transferred in one cycle — a wider bus means faster data transfer.
Address Bus
DirectionUnidirectional — carries addresses only from CPU (MAR) → Memory/I/O devices. One-way only.
ContentCarries memory addresses — specifies which location in RAM to read from or write to
WidthWidth determines addressable memory: a 32-bit address bus can address 2³² = 4GB of RAM
Data Bus
DirectionBidirectional — carries data in both directions: CPU ↔ Memory ↔ I/O devices
ContentCarries actual data and instructions between the MDR and memory or I/O
WidthA 64-bit data bus transfers 64 bits per cycle — wider bus = more data per transfer
Control Bus
DirectionBidirectional — carries signals both to and from the Control Unit
ContentCarries control signals: read, write, clock, interrupt, memory request, bus request
FunctionCoordinates and synchronises all CPU operations — tells components when to act
Bus Width & Performance
Key conceptBus width = number of parallel wires. More wires = more bits transferred simultaneously
Example8-bit bus → 8 bits/cycle. 64-bit bus → 64 bits/cycle. 8× faster data transfer
BottleneckA narrow bus can become a performance bottleneck even if the CPU itself is very fast
✏️ Exam Short Note — If asked "Explain the difference between the address bus and the data bus"
The address bus is unidirectional — it carries memory addresses only from the CPU to memory, specifying which location to access. The data bus is bidirectional — it carries actual data in both directions between the CPU and memory or I/O devices. The address bus specifies the location (WHERE); the data bus carries the content (WHAT). A wider bus in either case increases the amount of information that can be transferred per clock cycle.
📖 IB Definition — Processor Types
A processor is an integrated circuit that executes program instructions. A single-core processor has one processing unit and executes instructions sequentially. A multi-core processor contains two or more independent processing units (cores) on a single chip, enabling true parallel execution of multiple instruction streams. A co-processor is a supplementary processor that handles specialised tasks to offload the main CPU.
Single-Core Processor
DefinitionContains one processing unit that executes one instruction stream at a time — sequential processing
LimitationCannot genuinely multitask — appears to by switching rapidly between tasks (time-slicing)
UseOlder computers, simple embedded systems, low-power devices where cost matters
Multi-Core Processor
DefinitionMultiple independent processor cores on a single chip (dual, quad, octa-core etc.)
AdvantageTrue parallelism — each core executes its own thread simultaneously; improves performance for multi-threaded applications
LimitationNot all software is written to use multiple cores — poorly optimised apps see little benefit
UseModern smartphones, laptops, desktops, servers — virtually all current computing
Co-Processors
DefinitionA specialist processor designed to handle a specific type of task, working alongside the main CPU
GPUGraphics Processing Unit — thousands of small cores for parallel computation; used for rendering, AI
FPUFloating Point Unit — handles decimal/floating-point arithmetic much faster than the main ALU
NPUNeural Processing Unit — accelerates AI inference tasks (e.g. face recognition, voice assistants)
Comparing Processor Types
Single vs MultiSingle: sequential, simpler, cheaper. Multi: parallel, better performance, more complex, more power
Exam tipWhen asked to compare, always use "whereas" or "however" to contrast clearly
IB linkCo-processors connect to A1.1.2 (GPU) and A4 (Machine Learning uses GPU/NPU)
✏️ Exam Short Note — If asked "Outline one advantage of a multi-core processor over a single-core processor"
A multi-core processor contains multiple independent processing units on a single chip; each core can execute its own thread of instructions simultaneously. This enables true parallel processing, meaning multiple applications or tasks can run concurrently without each having to wait for the other to finish, resulting in significantly improved performance for multi-threaded workloads.
📖 IB Definition — Fetch–Decode–Execute Cycle
The Fetch–Decode–Execute (FDE) cycle is the sequence of steps that the CPU continuously repeats to process instructions. During the Fetch phase, an instruction is retrieved from memory. During the Decode phase, the Control Unit interprets what the instruction requires. During the Execute phase, the instruction is carried out. This cycle repeats billions of times per second, driven by the system clock.
1
FETCH
Retrieve the instruction from memory
PC→MARThe address of the next instruction is copied from the Program Counter to the Memory Address Register
MAR→RAMThe address in MAR is sent along the address bus to RAM, requesting the instruction at that location
RAM→MDRRAM sends the instruction back along the data bus into the Memory Data Register
MDR→IRThe instruction is transferred from MDR into the Instruction Register, ready for decoding
PC+1 The Program Counter is incremented to point to the address of the next instruction
2
DECODE
Interpret what the instruction means
The Control Unit reads the binary instruction currently held in the Instruction Register (IR)
The CU identifies the operation code (opcode) — what type of operation is required (e.g. ADD, LOAD, STORE, JUMP)
The CU identifies the operands — what data is needed and where it is located (in a register or memory)
The CU sends appropriate control signals via the control bus to prepare the necessary components for execution
3
EXECUTE
Carry out the instruction
If arithmetic/logical: the ALU performs the operation on the operands; result is stored in the Accumulator (AC)
If memory read: data is fetched from RAM via MAR/MDR into a register
If memory write: data from a register is written back to RAM via MAR/MDR
If jump/branch: the PC is updated to a new address, changing the sequence of execution
The cycle then repeats — the CPU immediately begins fetching the next instruction
✏️ Exam Short Note — If asked "Describe the stages of the Fetch–Decode–Execute cycle"
Fetch: The address in the PC is copied to the MAR; the instruction at that address in RAM is sent along the data bus to the MDR; it is then transferred to the IR; the PC is incremented. Decode: The Control Unit reads the instruction in the IR, identifies the operation and operands, and sends control signals to relevant components. Execute: The operation is carried out — the ALU performs calculations with the result stored in the AC, or data is read from/written to memory. The cycle then repeats for the next instruction.
📖 IB Definition — Graphics Processing Unit (GPU)
A Graphics Processing Unit (GPU) is a specialised co-processor originally designed to accelerate the rendering of graphics. Unlike the CPU which has a few powerful cores optimised for sequential tasks, the GPU contains thousands of smaller, simpler cores designed to perform the same operation on many data points simultaneously — a paradigm known as SIMD (Single Instruction, Multiple Data). This parallel architecture makes GPUs exceptionally efficient for tasks involving large-scale mathematical operations such as matrix multiplication.
GPU Architecture
CoresThousands of smaller, simpler cores (CUDA cores in NVIDIA, Stream Processors in AMD) vs CPU's few powerful cores
SIMDSingle Instruction, Multiple Data — executes one instruction across thousands of data points simultaneously
VRAMHas its own high-bandwidth video memory (VRAM) — much faster access than system RAM for graphical data
ClockGPU cores run at lower individual clock speeds than CPU cores but compensate through massive parallelism
Real-World Applications
GamingRenders millions of pixels per frame in 3D games, applying lighting, shading and textures in real time
AI/MLTrains deep learning neural networks — matrix multiplications in CNNs perfectly suited to parallel architecture
ScienceWeather modelling, molecular dynamics, physics simulations — all require massive parallel computation
VideoReal-time video encoding/decoding (H.265, AV1) — used in streaming platforms and video editing
CPU vs GPU — Side-by-Side Comparison
FeatureCPUGPU
Number of cores4–32 powerful coresThousands of simple cores
Clock speed per core3–6 GHz1–2 GHz per core
Optimised forSequential, complex tasksParallel, repetitive tasks
MemorySystem RAM (DDR5)VRAM (GDDR6/HBM)
Best use caseOS, apps, logic, branchingGraphics, AI, simulation
IB relevanceA1.1.1 CPU componentsA1.1.2 + A4 Machine Learning
✏️ Exam Short Note — If asked "Outline why a GPU is suitable for training a neural network"
Training a neural network involves performing large numbers of matrix multiplications across massive datasets simultaneously. A GPU contains thousands of smaller processing cores that can execute the same mathematical operation on many data points in parallel (SIMD architecture). This parallel processing capability means a GPU can perform these matrix operations far more efficiently than a CPU, significantly reducing the time required to train a deep learning model.

📋 CASE STUDY 1
Software Development via Cloud Platform (PaaS)
A team of software developers at a tech startup uses a Platform as a Service (PaaS) environment accessed via their laptops to collaboratively build a web application. The PaaS provider runs all computation on remote servers, and the developers interact with it through a browser. Each developer's laptop has a dual-core CPU running at 2.4 GHz with 8 GB of RAM.
Q1a
Outline the function of the accumulator in the CPU of each developer's laptop. [2]
▶ Show Mark-Scheme Answer
✓The accumulator stores intermediate arithmetic and logic results / holds operand data; [1]
✓…reducing the number of accesses to slower RAM during a sequence of calculations; [1]
💡 Examiner note: "Stores data" alone = 0 marks. Must specify arithmetic/logic results AND give the reason (reducing memory accesses).
Q1b
Explain how the Program Counter (PC) and Memory Address Register (MAR) interact during the Fetch phase. [4]
▶ Show Mark-Scheme Answer
✓The PC holds the memory address of the next instruction to be fetched; [1]
✓This address is copied from the PC to the MAR; [1]
✓The MAR sends the address along the address bus to RAM, requesting the instruction; [1]
✓The PC is then incremented by 1 so it points to the address of the next instruction for the subsequent cycle; [1]
💡 Most missed mark: The PC increment. Always include "PC is incremented (+1)" as a separate point.
Q1c
State one difference between the address bus and the data bus in the laptop's CPU. [2]
▶ Show Mark-Scheme Answer
✓The address bus is unidirectional (carries addresses only from CPU to memory); [1]
✓whereas the data bus is bidirectional (carries data in both directions between CPU and memory/I/O); [1]
Alternative: Address bus carries memory addresses; data bus carries actual data/instructions;
💡 Use contrast words like "whereas" or "however" when stating differences — it signals to the examiner that you understand both sides.
Q1d
Outline one benefit of using a dual-core processor compared to a single-core processor for the developers' laptops. [2]
▶ Show Mark-Scheme Answer
✓A dual-core processor has two independent processing cores; [1]
✓allowing two threads/tasks to be executed simultaneously (true parallelism), improving overall system performance; [1]
💡 Always give two linked ideas: WHAT the multi-core has (multiple cores) + WHY it helps (simultaneous execution / parallelism).
📋 CASE STUDY 2
Hospital AI System — Deep Learning CNN for Medical Imaging
A large hospital has implemented a convolutional neural network (CNN) to automatically analyse chest X-ray images and predict the likelihood of pneumonia. The system was trained on a dataset of 200,000 labelled X-ray images. The hospital's IT team had to choose between training the model on standard CPU servers or purchasing dedicated GPU clusters. They ultimately chose GPU clusters, reducing training time from an estimated 3 weeks to 18 hours.
Q2a
Outline one reason why a GPU is recommended when training the CNN model using the large dataset. [2]
▶ Show Mark-Scheme Answer
✓Deep learning involves many matrix operations (multiplications and convolutions); [1]
✓GPUs have many smaller cores designed explicitly for parallel operations, significantly speeding up training time; [1]
Alternative: Large datasets increase computational demand; training on CPU alone would be too time-consuming / GPUs speed up training significantly;
💡 The GPU formula: What AI needs (parallel matrix ops) + What GPU provides (thousands of parallel cores). "Parallel" is the essential keyword.
Q2b
Explain the architectural difference between a CPU and a GPU that makes the GPU more suitable for training the CNN. [4]
▶ Show Mark-Scheme Answer
✓A CPU has a small number of powerful, complex cores (typically 4–32) optimised for sequential processing; [1]
✓A GPU has thousands of smaller, simpler cores designed to perform the same operation on many data points simultaneously; [1]
✓CNN training requires repeating the same mathematical operations (matrix multiplications) across millions of data points; [1]
✓The GPU's parallel architecture (SIMD) allows it to perform these operations in parallel, dramatically reducing training time; [1]
💡 Link CPU limitation → GPU strength → why CNN benefits. The context (CNN/hospital) is there to frame your answer — always refer back to the scenario.
Q2c
Describe the role of the Control Unit during the execution of one instruction in the CPU. [3]
▶ Show Mark-Scheme Answer
✓The Control Unit reads the instruction currently held in the Instruction Register (IR); [1]
✓It decodes the instruction — identifying the operation (opcode) and the operands required; [1]
✓It sends control signals via the control bus to the appropriate components (e.g. ALU, registers, memory) to execute the instruction; [1]
💡 Three-mark answers need three clear, distinct statements. Use the structure: reads → decodes → sends signals.
📋 CASE STUDY 3
Autonomous Vehicle — Real-Time Processing
A technology company is developing a self-driving car. The vehicle must process real-time data from cameras, LiDAR sensors and radar simultaneously, run computer vision algorithms to detect obstacles, and make driving decisions in milliseconds. The onboard computing system includes a 64-core CPU, a dedicated GPU, and a custom NPU (Neural Processing Unit) for running the AI inference model.
Q3a
Outline why a multi-core CPU is more appropriate for this self-driving car system than a single-core CPU. [2]
▶ Show Mark-Scheme Answer
✓The vehicle must process multiple simultaneous tasks (camera feeds, LiDAR, radar, decision-making); [1]
✓A multi-core CPU can assign each task to a separate core, processing them in parallel — a single-core processor would need to switch between tasks sequentially, introducing dangerous delays; [1]
💡 Great answers reference the scenario — "dangerous delays" shows real understanding. Always connect the technical concept to the real-world consequence in context.
Q3b
Explain the role of a co-processor in the vehicle's computing system. Use the GPU or NPU as an example. [4]
▶ Show Mark-Scheme Answer
✓A co-processor is a specialist processor that handles specific computational tasks alongside the main CPU; [1]
✓The GPU processes camera image data in real time — its thousands of parallel cores rapidly apply computer vision algorithms to detect lane markings and obstacles; [1]
✓The NPU runs the AI inference model (e.g. object classification) — specialist hardware accelerates this faster than the CPU alone; [1]
✓By offloading these tasks to co-processors, the main CPU is freed to handle decision-making, system coordination and other logic, improving overall system performance; [1]
💡 When "explain with example" — define the concept, give the specific example from the scenario (GPU/NPU), AND explain the impact. Four-mark answers need all three.
Q3c
Describe the role of the three system buses in transferring sensor data into the vehicle's CPU for processing. [3]
▶ Show Mark-Scheme Answer
✓The address bus (unidirectional) carries the memory address of where the sensor data is stored — from the CPU to memory, specifying which location to access; [1]
✓The data bus (bidirectional) transfers the actual sensor data between memory/I/O devices and the CPU's MDR; [1]
✓The control bus carries signals from the Control Unit (such as read/write) that coordinate and synchronise the transfer of data; [1]
💡 For bus questions: name it, state direction (uni/bi), state what it carries, and link to the scenario. One mark per bus.
📋 CASE STUDY 4
Video Game Studio — High-Performance Rendering
A video game development studio is producing a realistic open-world game. During development, their workstations need to: compile large codebases, run physics simulations, and render photorealistic 3D scenes using ray tracing at 4K resolution. The studio upgrades their workstations from quad-core CPUs to systems with 16-core CPUs and dedicated GPUs with 16 GB of VRAM.
Q4a
Outline one reason why upgrading from a quad-core to a 16-core CPU would benefit the studio's developers. [2]
▶ Show Mark-Scheme Answer
✓A 16-core CPU has four times as many independent processing units; [1]
✓allowing more tasks (such as code compilation, physics simulation and asset processing) to be performed simultaneously, reducing overall development time; [1]
Q4b
Explain why a GPU with dedicated VRAM is necessary for 4K ray tracing in this studio's workflow. [4]
▶ Show Mark-Scheme Answer
✓Ray tracing at 4K requires calculating the colour of millions of pixels per frame, each requiring multiple light-ray calculations; [1]
✓The GPU's thousands of parallel cores can compute many pixel values simultaneously, which is not possible with a CPU's few sequential cores; [1]
✓VRAM (video RAM) stores the large frame buffer, textures and geometry data needed for rendering — 4K resolution generates very large data that must be accessed rapidly; [1]
✓VRAM has much higher memory bandwidth than system RAM, allowing the GPU to rapidly read/write rendering data without bottlenecks; [1]
💡 4-mark "explain" answers need depth. Connect each point to the specific scenario — mention "4K", "ray tracing", "VRAM" from the context.
Q4c
Describe what happens in the Instruction Register (IR) and Accumulator (AC) when the CPU executes the instruction: ADD 5, 3. [3]
▶ Show Mark-Scheme Answer
✓The instruction "ADD 5, 3" is fetched from memory and held in the IR, where the Control Unit decodes it to identify that an addition operation is required with operands 5 and 3; [1]
✓The CU directs the ALU to perform the addition: 5 + 3 = 8; [1]
✓The result (8) is stored in the Accumulator (AC), which holds this intermediate result and reduces the need to write it back to RAM immediately; [1]
💡 Trace-style questions: always go step by step through IR → CU decode → ALU computes → AC stores result. Don't jump straight to "the answer is 8".
