Topic Notes — A1.1.1 CPU Components
ALU · Control Unit · Registers · Buses · Processors · FDE Cycle
CPU Architecture Diagram
ALU
Arithmetic Logic Unit
Performs ALL calculations and logical decisions inside the CPU.
Arithmetic: + − × ÷ on binary numbers
Logical: AND, OR, NOT, XOR, comparisons
All results go to the Accumulator (AC)
CU
Control Unit
The manager of the CPU — coordinates all activity.
Fetches instructions from memory
Decodes instructions held in IR
Sends control signals to all components
Registers — 5 types
Ultra-Fast CPU Storage
PC — address of NEXT instruction
IR — CURRENT instruction being decoded
MAR — memory ADDRESS to access
MDR — DATA read from / written to RAM
AC — result of last ALU operation
Buses — 3 types
Electrical Pathways
Address Bus — addresses MAR→RAM · UNIDIRECTIONAL
Data Bus — actual data MDR↔RAM · BIDIRECTIONAL
Control Bus — read/write signals CU→all · BIDIRECTIONAL
Fetch–Decode–Execute Cycle
STEP 1 · FETCH
Fetch
1. PC → MAR (address)
2. MAR → RAM via address bus
3. RAM → MDR via data bus
4. MDR → IR (instruction)
5. PC incremented (+1)
STEP 2 · DECODE
Decode
CU reads IR
Identifies the operation
Identifies operands
Sends control signals
Prepares components
STEP 3 · EXECUTE
Execute
ALU performs operation
Result stored in AC
May write result to RAM
Cycle repeats
Billions of times / second
Processor Types & GPU
Single-Core
Single-Core Processor
One processing unit — executes one instruction stream sequentially. Older computers. Cannot multitask genuinely.
Multi-Core
Multi-Core Processor
Multiple independent cores on one chip (dual/quad/octa-core). Each core runs its own thread — true parallelism for multiple applications simultaneously.
Co-Processors
Co-Processors
Specialist chips that offload specific tasks from the CPU. Examples: GPU (graphics/AI), FPU (floating-point), NPU (neural networks), DSP (audio/video).
GPU — A1.1.2
Graphics Processing Unit
Thousands of smaller cores for parallel computation. Used for: 3D gaming, AI/ML training (matrix ops), scientific simulation, video encoding. Key: SIMD parallel architecture.

Q1(a) — HL Paper 1 Specimen · A1.1.1
[2 marks]
Context: A team of programmers use PaaS via their laptops to develop a software application.
Outline the function of an accumulator.
Outline = brief account2 marks = 2 separate pointsPoints separated by semicolons
✅ MARK SCHEME ANSWER
✓To store intermediate arithmetic and logic results / hold operand data; [1]
✓…to reduce the number of memory accesses by holding intermediate results; [1]
Alt:Acts as a temporary storage location; which stores values and results from arithmetic and logical operations;
💡 Examiner Tip
Saying "the accumulator stores data" earns zero — too vague. You must specify it stores results of arithmetic/logic operations. Second mark: explain WHY — reduces memory accesses, speeding up processing. Always look for two linked ideas for [2] questions.
Practice Q — Registers & FDE Cycle · A1.1.1
[4 marks]
Explain how the Program Counter (PC) and Memory Address Register (MAR) interact during the fetch phase of the FDE cycle.
Explain = detailed account with reasonsLink cause and effect4 points needed
✅ MARK SCHEME ANSWER
✓The PC holds the address of the next instruction to be fetched from memory; [1]
✓This address is copied from PC to MAR; [1]
✓MAR sends address along the address bus to RAM to request the instruction; [1]
✓The PC is incremented (+1) so it points to the next instruction for the following cycle; [1]
💡 Examiner Tip
For "explain" questions always connect WHAT to WHY. Don't just say "PC goes to MAR" — explain this is so the CPU knows which memory address to access. Use "address bus" specifically. The PC increment is the most commonly missed mark point in FDE questions.
Q4(c) — HL Paper 1 Specimen · A1.1.2 GPU
[2 marks]
A hospital uses a deep learning CNN to analyse chest X-rays and predict likelihood of pneumonia.
Outline one reason a GPU is recommended when training a deep learning CNN model using a large dataset.
Parallel processingMatrix operationsMany smaller coresTraining speed
✅ MARK SCHEME ANSWER
✓Deep learning involves many matrix operations (multiplications and convolutions); [1]
✓GPUs have many smaller cores designed for parallel operations, significantly speeding up training; [1]
Alt:Large datasets increase computational demand; training on CPU alone would be too time-consuming;
💡 The GPU Answer Formula
Always link TWO things: (1) what AI/ML needs — parallel matrix operations on large data, and (2) what GPU provides — thousands of smaller cores for parallel processing. Without the link you get only 1/2. The magic word is always "parallel".
