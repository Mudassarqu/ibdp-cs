How text is stored

Characters are stored using agreed encoding standards, so that the same pattern of bits means the same letter on every machine in the world. ASCII came first; Unicode extended it to every writing system.

1.1Why encoding standards exist

Before 1963 every manufacturer used its own scheme for turning letters into numbers. Two machines could not exchange text reliably. ASCII — the American Standard Code for Information Interchange — was created to fix exactly that.

ASCII began as a 7-bit code, giving 27 = 128 characters: enough for the English alphabet in both cases, the digits, punctuation and control characters. As computing spread, an 8-bit extended ASCII raised this to 28 = 256, with the extra slots used mostly for Western European accented letters.

The rule worth memorising

The last five bits give the letter's position in the alphabet: a = 00001, b = 00010, c = 00011, and so on up to z = 11010.

The first three bits give the case: 011 = lowercase, 010 = uppercase.

Two shortcuts from the textbook

If the last five bits are 00000, it is almost certainly a space (00100000).

If the first three bits are neither 011 nor 010, you are probably looking at a digit, a punctuation mark or a control character — not a letter.

1.3Why Unicode had to be invented

Extended ASCII gave every country 256 slots — but no agreement on what to put in them. Nordic countries encoded their own letters; Japan ran four mutually incompatible systems. That barely mattered while machines rarely talked to each other. Then the internet arrived.

The Unicode Consortium was formed in 1991 to give every character in every language a single unique number, while staying backwards compatible with ASCII. Version 15.0 (2022) encodes 149,186 characters — Latin, Cyrillic, Greek, Arabic, Chinese, mathematical symbols and emoji.

The lead-byte pattern

2.1Where digital images began

In 1957 Russel Kirsch scanned a photograph of his son Walden, producing the first digital image ever made. Everything from phone cameras to medical imaging descends from that scan.

2.2What a bitmap is

A bitmap — also called a raster image — reproduces a picture using a grid of pixels, each assigned a colour. The number of bits used to describe one pixel's colour is the colour depth (or bit depth).

The formula you will be examined on
image size = width (pixels) × height (pixels) × colour depth (bits per pixel)
13 × 10 × 1 = 130 bits (130 / 8 = 16.25 bytes)

Why the real file is always bigger

That calculation covers the pixel data only. A real file also stores metadata and header information — dimensions, colour depth, creation date, author, camera settings — so the CPU can read and display the image correctly. Exam questions often add a percentage for this.

2.3Improving quality, lever 1: resolution

More pixels means more detail. But the screen matters too: a 1024 × 768 image looks sharp on a phone and poor on a cinema screen, because the phone packs those pixels into far fewer inches — a higher PPI (pixels per inch). The trade-off for higher resolution is always a larger file.

2.4Improving quality, lever 2: colour depth

Colours available
number of colours = 2colour depth   →   28 = 256

Too few bits and gradients turn into visible steps, called banding. More bits means more colours but a larger file.

2.5Inside one pixel — RGB

Most modern screens are 24-bit: three lights per pixel — red, green and blue — each stored in one byte with a range of 0 to 255. That gives 224 = 16,777,216 colours, comfortably more than the roughly 10 million a human eye can distinguish.

R 216 = 11011000 G 190 = 10111110 B 199 = 11000111 stored as 24 bits → 11011000 10111110 11000111 in hexadecimal → #D8BEC7

This is why hexadecimal from A1.2.1 matters here: graphics tools show colours in hex because two hex digits describe one byte exactly.

3.1Sound starts analogue

Sound is a continuous analogue signal — smooth variations in air pressure. A microphone captures it, and an analogue-to-digital converter (ADC) turns it into binary. A computer cannot store a smooth curve, so it stores measurements of one instead.

3.2Sampling

Sampling means measuring the amplitude (loudness) of the wave at regular intervals. How often this happens is the sample rate, measured in hertz.

3.3Bit depth

Sample rate decides how often you measure; bit depth decides how precisely each measurement is recorded. More bits means more possible amplitude values, so each sample sits closer to the true height of the wave.

Audio storage
bits = sample rate × bit depth × channels × seconds

One second of CD-quality stereo audio:

44,100 samples/s × 16 bits × 2 channels = 1,411,200 bits per second = 176,400 bytes per second

Watch the channels

Stereo means two channels, so the figure doubles. Mono is one. Dropping this factor is the single most common error in audio calculation questions.

3.4Storage formats and compression

Lossless compression

Reduces file size with no loss of quality — the original data can be perfectly reconstructed. Example: FLAC.

Lossy compression

Permanently removes parts of the signal the human ear is least likely to notice. Smaller files, but the discarded audio can never be recovered. Example: MP3.

4.1What a video file contains

A video is a container format — MP4, MKV or AVI — holding several components: frames (the visual data), audio tracks, metadata, and subtitles or closed captions. Audio is stored exactly as in the previous section; metadata and subtitles are stored as text.

4.2Frames

Video is a sequence of still images shown in quick succession — usually 24 to 60 frames per second — which creates the illusion of motion, exactly like a flipbook. In raw form each frame is stored like any bitmap, with every pixel carrying an RGB value.

Uncompressed video storage
bits = width × height × colour depth × frame rate × seconds

Ten minutes of uncompressed Full HD at 30 fps:

one frame = 1920 × 1080 × 24 = 49,766,400 bits total = 49,766,400 × 30 × 600 = 895,795,200,000 bits ≈ 104 GiB

Why compression is not optional

A hundred gigabytes for ten minutes is unstreamable and unstorable. Every real video file is compressed — which is why the syllabus asks you to explain how.

4.3The YUV conversion

Before compression, frames are often converted from RGB to a colour model such as YUV. YUV separates luminance (brightness) from colour information. The human eye is far more sensitive to changes in brightness than to fine colour detail, so the colour channels can be stored at lower precision without a visible difference — which makes the compression that follows far more effective.

4.4The two compression techniques

Spatial compression — intraframe

Works within a single frame. Removes redundant information inside that frame — reducing colour depth or fine detail levels the viewer will not miss.

Temporal compression — interframe

Works between consecutive frames. Stores only what changed from one frame to the next. It is predictive: frame content is predicted from the preceding — and sometimes following — frames, and only the differences are stored.

A fixed camera on a static scene is where temporal compression wins hugely: the background is identical frame after frame, so almost nothing needs storing. A fast-cutting action sequence gives it far less to work with.

Eight bits on their own carry no meaning. The representation system is what turns a pattern into a value — and the syllabus names several, each with its own purpose and limitation.

5.1Unsigned binary

Straightforward place value, positive integers only. In 8 bits: 0 to 255. This is the system from A1.2.1.

5.2Two's complement — the standard for signed integers

The MSB indicates the sign: 0 positive, 1 negative. To negate a number, invert every bit, then add 1.

00000101 = +5 invert → 11111010 add 1 → 11111011 = −5

The cost is range. Instead of 0 to 255, an 8-bit two's complement number runs from −128 to +127 — the positive range is effectively halved. Crucially, there is only one representation of zero, which is why this is the system computers actually use.

5.3One's complement

MSB indicates the sign; to negate, simply invert all the bits — no add.

00000101 = +5 11111010 = −5

Range −127 to +127, and it has two zeros: positive zero (00000000) and negative zero (11111111). That ambiguity causes problems in arithmetic and logical operations, which is why two's complement is preferred.

5.4Sign-magnitude

MSB is purely a sign flag; the remaining seven bits hold the magnitude as ordinary unsigned binary.

00000101 = +5 10000101 = −5

Range −127 to +127, and again two zeros (00000000 and 10000000). Simple to read, but less efficient than two's complement.

5.5Binary-coded decimal (BCD)

Each decimal digit is encoded separately as its own 4-bit code, rather than converting the whole number at once.

0100 0101 = 45 (0100 = 4, 0101 = 5)

Where BCD earns its place

Exact decimal representation — financial applications and digital clocks — because it avoids the rounding errors other systems introduce.

Why it is not used generally

Four bits per digit makes it less space efficient than pure binary, and arithmetic is more complex because carry and overflow need extra handling.

5.6Gray code (reflected binary code)

A system in which two successive values differ by exactly one bit.

The exam example: a robotic arm

A rotary encoder reports the arm's angle as a binary output. With standard binary, a small mechanical vibration during a transition like 011 → 100 could cause several bits to change at slightly different moments, producing a wildly wrong reading. With Gray code only one bit ever changes, so the risk of those transition errors is minimised.

5.7Excess-N (biased representation)

A fixed bias N is added to the real value to encode it, and subtracted to decode it. The effect is that all signed integers appear as non-negative binary numbers, so they sort and compare correctly in plain binary order.

Excess-3: 2 + 3 = 5 → 0101 −2 + 3 = 1 → 0001 Excess-127: 127 + 127 = 254 → 11111110 −127 + 127 = 0 → 00000000

Without the bias, −127 in sign-magnitude (10000001) looks larger in binary than +127 (01111111). After biasing, the ordering is correct.

5.8Fixed-point representation

Real numbers stored by fixing the position of the binary point. Fractional place values to the right of the point are ½, ¼, ⅛, 1⁄16.

5.25 in 8 bits, 4 integer + 4 fractional: integer part 0101 = 5 fractional part 0100 = 0.25 (0×½ + 1×¼ + 0×⅛ + 0×1⁄16) combined 0101.0100

Simple and fast, with no complex operations to adjust the point — but limited range and precision. With a 4-bit signed integer part the range is just −8 to 7.9375, with a smallest step of 0.0625.

5.9Floating-point representation (IEEE 754)

For very large or very small numbers. Single precision uses 32 bits, split into three parts:

ComponentBitsPurpose
Sign10 positive, 1 negative
Exponent8Scales by a power of two; stored in Excess-127 biased form
Mantissa23The significant digits; the leading 1 is not stored

Far greater range than fixed-point and essential in scientific computing, engineering and graphics — but still not precise enough to represent every decimal exactly, so rounding errors remain. It is also slower, often needing dedicated hardware.
