Why computers use binary

Binary was not the obvious choice. Decimal, ternary and quaternary machines were all built first — and understanding why binary won explains almost everything else in this topic.

1.1Three systems were tried before binary

Charles Babbage designed the Analytical Engine in the 19th century using decimal (base-10). That seemed the sensible choice — people already counted in tens, so a machine that did the same would be easy to understand.

In 1958 the Soviet Union built the Setun computer using ternary (base-3). Over fifty were made for schools and research institutes to explore whether three-state logic was better. Others experimented with quaternary (base-4). All of them lost to binary.

1.2Why binary won — three reasons

Binary (base-2) has only two states: 1 and 0. Decimal has ten (0–9). That restriction turns out to be an enormous advantage.

Reason 1 — it matches the hardware

A transistor is a switch. It is either on or off. Binary's two states map directly onto those two physical states: on = 1, off = 0. A base-10 machine would need each component to hold ten distinguishable voltage levels, which is far harder to build.

Reason 2 — it matches Boolean algebra

Boolean algebra is the mathematics of true and false. Because binary inputs are 1 (on / true) and 0 (off / false), complex operations can be built out of simple logic gates — which is exactly what topics A1.2.3 to A1.2.5 are about.

Reason 3 — it is reliable in noisy conditions

Noise is unwanted electrical disturbance that shifts voltages slightly. With only two states, a small drift still reads as the same value. In a ten-state system the gap between levels is much smaller, so the same drift can flip a digit and corrupt the data.

1.3What this means for the rest of the topic

Because every piece of data on the machine ends up as binary, we need agreed systems for turning integers, characters, images, audio and video into 1s and 0s. A1.2.1 covers the number systems themselves — base-2, base-10 and base-16 — and how to convert between them. A1.2.2 then covers how those numbers are used to store real data.

2.1Start with the system you already know

In decimal, each column is worth ten times the one to its right, because the base is 10. Take the number 1024:

(1 × 1000) + (0 × 100) + (2 × 10) + (4 × 1) = 1024

2.2Binary works identically — the base is just 2

Each column is worth twice the one to its right. Take the binary number 0110:

(0 × 8) + (1 × 4) + (1 × 2) + (0 × 1) = 6

No 8s, one 4, one 2, no 1s — so 4 + 2 = 6. To avoid confusion we write the base as a subscript: 0110₂ = 6₁₀.

2.3Bits, nibbles and bytes

A bit is a single binary digit, 1 or 0. Four bits make a nibble; eight bits make a byte. We normally work in 8-bit numbers and pad shorter values with leading zeros. Decimal 33 as a byte:

The mistake examiners see every year

With 8 bits there are 256 different possibilities, but the largest value you can store is 255 — because zero takes up one of those 256 slots. So 11111111₂ = 255₁₀, not 256.

Adding one more bit doubles the range: n bits give 2n possibilities, from 0 to 2n − 1.

2.4Prefixes — the KB / KiB trap

Lowercase b means bits; uppercase B means bytes. There are then two separate prefix families: the base-10 family (kilo, mega, giga — powers of 1000) and the base-2 family the IEC introduced in 1999 (kibi, mebi, gibi — powers of 1024).

Review question from the textbook

Two internet providers advertise at the same price. One offers 100 Mb/s, the other 100 MB/s. Which is faster, and by how much?

Answer

100 MB/s is eight times faster. 100 megabytes = 800 megabits, because there are 8 bits in a byte. Internet speeds are almost always quoted in bits per second, which is why the advertised number looks so large.

3.1Binary → decimal, method 1: positional notation

The most reliable method, and the one to use under exam pressure.

  1. Starting from the right, write the place values above each bit: 1, 2, 4, 8, 16, 32, 64, 128.
  2. Add up every place value that has a 1 underneath it.

Converting 10111011₂:

128 + 32 + 16 + 8 + 2 + 1 = 187

Top tip from the textbook

Always write the place values down first. Trying to hold them in your head is where the silly mistakes come from.

3.2Binary → decimal, method 2: doubling

  1. Start at the leftmost bit — the most significant bit.
  2. Double the running total and add the next bit.
  3. Repeat until every bit has been used.

Common mistake

Start from the most significant bit (left), not the least significant bit (right). Starting from the wrong end gives a completely different — and wrong — answer.

3.3Decimal → binary, method 1: division

  1. Divide the decimal number by 2.
  2. Write down the quotient and the remainder (always 0 or 1).
  3. Repeat with the new quotient until the quotient reaches 0.
  4. Read the remainders bottom to top — the first remainder is the least significant bit.

Common mistake

Building the remainders in the order you wrote them. The first remainder is the LSB, so the binary number is read from the bottom of the table upwards.

3.4Decimal → binary, method 2: subtraction

  1. Write the 8-bit place values: 128, 64, 32, 16, 8, 4, 2, 1.
  2. Take the largest place value. If it is bigger than your number, write 0 underneath.
  3. If it fits, write 1, subtract it, and carry the remainder to the next place value.
  4. Repeat across the row.

4.1What hexadecimal is

Hexadecimal is base-16. It needs sixteen symbols, so after 0–9 it borrows letters: A = 10, B = 11, C = 12, D = 13, E = 14, F = 15.

That table is the whole topic. Learn those sixteen rows and every hex conversion becomes lookup rather than arithmetic.

4.2Why computer scientists use it

It maps perfectly onto binary

One hex digit is exactly four bits — one nibble. 1111₂ = F₁₆. No arithmetic is needed to move between the two.

It is far more compact

11010110₂ becomes D6₁₆. Two characters instead of eight, which is why hex appears in debugging tools, memory dumps, assembly language and colour codes.

4.3Binary → hexadecimal

  1. Split the byte into two nibbles of 4 bits.
  2. Work out the decimal value of each nibble.
  3. Convert each to its hex symbol and join them.
01101011₂  →  0110 | 1011  →  6 and 11  →  6B₁₆

4.4Hexadecimal → binary

Exactly the reverse: split the digits, write each as 4 bits, join.

F2₁₆  →  F = 1111, 2 = 0010  →  11110010₂

4.5Decimal → hexadecimal

  1. Divide by 16 and record the remainder.
  2. Repeat with the quotient until the quotient is 0.
  3. Read the remainders upwards — the last one found is the most significant digit.

4.6Hexadecimal → decimal

  1. Convert each hex digit to its decimal value.
  2. Multiply by 16 raised to its position index, counting from 0 on the right.
  3. Sum the results.
2F₁₆  →  2 × 16¹ = 32   and   15 × 16⁰ = 15
32 + 15 = 47₁₀
