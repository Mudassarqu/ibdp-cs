Function and interaction of the main CPU components

A1.1.1Hodder pp. 2–4

Describe the functions and interactions of the main CPU components — the units, the registers, the buses and the processor configurations.

What the syllabus requires

Units: arithmetic logic unit (ALU), control unit (CU)  ·  Registers: IR, PC, MAR, MDR, AC  ·  Buses: address, data, control  ·  Processors: single-core, multi-core, co-processors  ·  a diagrammatic representation of the relationship between these components.

That last bullet is new and explicit — be ready to draw and label the diagram below in the exam.

The two units inside the CPU Hodder p. 2

The central processing unit (CPU) is often called the "brain" of the computer. It carries out the majority of the processing inside a device, and is made up of two main units.

  • Control unit (CU) — directs the operations of the processor. It is responsible for the fetch–decode–execute cycle, managing all three operations and directing the computer's memory, ALU and input/output devices to respond appropriately.
  • Arithmetic logic unit (ALU) — performs arithmetic operations (addition, subtraction, multiplication, division) and logic operations (AND, OR, XOR, NOT).

Drawing this in the exam

Work outwards: box the CPU first, put CU and ALU inside it, add the registers, draw RAM outside the box, then join them with three labelled lines — address, data, control. Label every component; unlabelled boxes earn nothing.

The five registers Hodder p. 3

Registers are very small amounts of storage available directly on the CPU, holding temporary data the CPU is working on.

RegisterWhat it holds
Instruction register (IR)When an instruction is fetched from memory it is held in the IR. This register holds the instruction currently being executed.
Program counter (PC)Holds the address of the next instruction to be fetched from memory. Once an instruction has been fetched, the PC updates to point to the next one.
Memory address register (MAR)Holds the memory address currently being fetched. The content of the PC is copied to the MAR, which provides this address to the memory unit so data and instructions can be read from or copied to that location.
Memory data register (MDR)Holds the data that has been fetched, or is about to be written to, the memory address currently in the MAR.
Accumulator (AC)Stores the intermediate arithmetic or logical results produced by the ALU.

The three buses Hodder p. 3

Buses transfer data between the CPU, memory, storage and peripherals. Bus width is measured in bits — the wider the bus, the more data it can transmit at one time.

BusCarriesDirection
Control busCommand and control signals from the CPU to other components and back — read/write operations, interrupt requests, clock signals for synchronization, status signals from hardware.Bidirectional
Data busThe data being processed, between CPU, memory and peripherals. Common widths are 8, 16, 32 and 64 bits.Bidirectional
Address busThe address to be read from or written to in memory. Its width determines the memory capacity of the system — a 32-bit address bus can address 232 locations.Unidirectional

Processor configurations Hodder p. 4

  • Single-core processor — a single processing unit, so it handles one task at a time. Found in low-end or older machines. It can run more than one application, but the CPU has to be shared between them, which can impact performance.
  • Multi-core processor — two or more cores running multiple instructions simultaneously: dual-core (2), quad-core (4), hexa-core (6), octa-core (8). Significantly faster, ideal for multitasking, gaming and servers. However, software must be written to take advantage of the extra cores; older software would run at a similar speed to a single-core processor.
  • Co-processor — a special processor with a specific job supporting the main CPU, built for a distinct purpose to achieve optimal performance. Tasks are offloaded by the CPU so they run in parallel. Examples: GPUs, audio processors, digital signal processors (DSPs).

Common mistake Hodder p. 4

Assuming more cores always means proportionally faster — that a dual-core is twice as fast, or a quad-core four times. The speed increase depends on how well the software can use multiple cores at once. Many programs are not designed to, so extra cores may make no noticeable difference. Memory speed and CPU design also affect performance.

What a GPU is Hodder p. 5

A graphics processing unit (GPU) is a specialized electronic circuit designed to accelerate the rendering of images, videos and animations by performing rapid mathematical calculations. It was initially developed for the demanding graphics workloads of video games and visual applications.

Its structure consists of thousands of small, efficient cores, allowing it to process multiple tasks simultaneously. This makes it exceptionally well-suited to computationally intensive applications, and has led to widespread adoption in scientific research, machine learning, artificial intelligence and cryptocurrency mining. By offloading these intensive tasks from the CPU, GPUs enhance overall system performance.

The sentence that earns the mark

Almost every GPU question comes back to one idea: the GPU has many small cores working in parallel, so it excels when the same operation must be applied to very many data points at once.

Say that, then give the context the question asks for — pixels for rendering, matrices for AI, hashes for mining.

The four application areas Hodder pp. 5–6

AreaHow the GPU contributes
Graphics processingA highly parallel structure performs many calculations simultaneously, well-suited to rendering the complex graphics in modern video games. It applies shaders and textures to 3D models — lighting, shading and texture mapping — enhancing realism.
Video processingAssists in decoding and encoding video files, making playback, streaming and editing more efficient and faster. Particularly helpful for 4K and higher resolution files.
AI and machine learningFrom the early 2000s, researchers recognised GPUs' potential for general-purpose calculation. Many AI models rely heavily on matrix and vector multiplications, and GPUs far outperform a CPU at processing these quickly. By the mid-2000s GPUs had become essential tools in AI, significantly reducing model training time.
Blockchain and cryptocurrency miningFrom 2010, GPUs significantly outperformed CPUs at solving cryptographic puzzles, such as finding the nonce in the hashing algorithm for proof of work. The 2017–2021 boom escalated demand, causing price rises and global shortages.

Why GPU demand fell back after 2023 Hodder p. 6

Three reasons the textbook gives: the volatility and reduced profitability of cryptocurrency mining lowered demand; manufacturers increased production to meet demand; and ASICs (Application-Specific Integrated Circuits), designed specifically for mining, largely replaced GPUs in many mining operations.

Design philosophies Hodder p. 7

  • CPU — a general-purpose processor. It handles many types of task: running the operating system, processing user input and managing programs. Good at tasks where decisions need to be made quickly and where different types of work happen at the same time.
  • GPU — a specialized processor. It focuses on specific types of task, made for processing large amounts of data in parallel. For example, GPUs process images and video because they can work on thousands of pixels at once.

Core architecture Hodder p. 7

The CPU has only a few cores, but each is very powerful and can handle many different instructions — working best one task at a time. CPUs also have branch prediction (guessing what will happen next) and out-of-order execution (working on tasks that are ready before others).

The GPU has many smaller cores. Individually they are less powerful than CPU cores, but there are thousands of them all working at the same time — ideal for rendering 3D images where many similar calculations must happen at once.

Memory access and power efficiency Hodder p. 7

The CPU uses a smaller, high-speed cache to get data quickly — useful when accessing small amounts of data many times. The GPU uses its own VRAM (video RAM), which has very high bandwidth, so it can move large amounts of data at once such as images and video. However, the GPU uses more power because it must process a lot of data at the same time.

Key information Hodder p. 8

CPUs are better for tasks requiring high-speed, complex decision-making and versatility. GPUs are better when the same operation needs to be performed on many data points simultaneously. For gaming, video editing and computational research (AI and machine learning), GPUs often significantly outperform CPUs.

Five axes of comparison

A "compare" question wants more than one axis. The syllabus names five: design philosophy, core architecture, processing power, memory access and power efficiency. Pick the number the marks demand, and refer to both processors in every point.

How they work together in a video game Hodder p. 8

The CPU handles the game's core logic — rules, physics calculations and AI behaviour — and processes player input, updating the game state. The GPU renders the visuals, processing vertex and pixel data to draw 3D objects, textures and effects such as lighting and shadows.

StageWhat happensUnit
1 · Player inputThe player presses a key to move a character. The input is processed, the character's position updated using game physics, and the new game state determined.CPU
2 · Data preparationThe new position and state data are prepared and sent to the GPU.CPU
3 · RenderingThe frame is updated with the character's new position, lighting and shading applied, and the scene rendered.GPU
4 · DisplayThe rendered frame is displayed on screen, giving immediate feedback to the player.GPU

What counts as primary memory Hodder p. 8

Primary memory stores the data and instructions the CPU needs to process tasks. It includes RAM, ROM, caches and registers — all used directly by the CPU.

RAM and ROM Hodder p. 9

RAM — random access memoryROM — read-only memory
HoldsInstructions and data for programs currently running. Opening an app loads it into RAM so the CPU can access it quickly.Instructions that are very rarely modified — principally the BIOS, located on the motherboard.
VolatilityVolatile — loses its contents when power is turned off. This is why you lose game progress unless you save.Non-volatile — does not lose its contents without power.
RoleLets a smartphone switch quickly between apps; leaving an app keeps it in RAM so you can return without reloading.The BIOS initializes and tests system hardware on startup, then loads the OS from secondary storage into RAM ready for the CPU.
Modern note—While "read only", most modern computers use flash memory, allowing updates and reprogramming so manufacturers can update their software.

Where the CPU looks for data Hodder p. 9

Cache memory is small but provides high-speed access compared to RAM. It acts as a buffer between the CPU and the slower RAM, storing frequently used data and instructions. There are three types — L1, L2 and L3 — each with different sizes and speeds. The closer to the CPU, the faster it is.

The three cache levels Hodder p. 10

LevelLocationSizeSpeed
L1Directly on the CPU. Each core usually has its own, split into L1i for instructions and L1d for data.32KB–128KB per coreFastest — accessed almost instantly
L2On the CPU like L1, or situated very close to it. Usually exclusive to a single core.256KB–2MB per coreFaster than L3, slightly slower than L1
L3Furthest from the CPU chip. May be shared across multiple cores.2MB–64MB sharedSlowest of the three, but still significantly faster than RAM

Cache hit and cache miss Hodder p. 10

  • Cache hit — the ideal scenario: the CPU requests data and it is found in the cache memory, so it can be processed very quickly.
  • Cache miss — the data is not found, necessitating retrieval from the slower main memory (RAM) or even slower storage (SSD/HDD), which causes a delay.

The percentage hit rate determines the efficiency and effectiveness of the cache. A low hit rate means the system suffers more from latency, hindering performance. Systems with a larger cache generally perform better, as do systems with more intelligent prefetching — predicting which data will be needed soon and loading it into cache ahead of time.

Top tip — the onion Hodder p. 10

Picture an onion. L1 is the very centre: smallest, tightly packed, closest to the core. L2 is the next layer out — still close, but not as quick. L3 is the outer layer: still important, but it takes a bit longer to get to.

New in the 2027 syllabus

The guide names "the relevance of the terms cache miss and cache hit" as its own bullet. Defining the two terms is only half the answer — you must also say what each does to performance: a hit avoids latency, a miss forces a slower retrieval, and the hit rate is what determines overall efficiency.

The three stages Hodder p. 11

The fetch–decode–execute cycle, also known as the instruction cycle, is the fundamental process a CPU uses to execute instructions.

  • Fetch — the CPU fetches an instruction from memory.
  • Decode — the CPU interprets the instruction and prepares the necessary operations to execute it.
  • Execute — the CPU performs the actions required by the instruction.

Little Man Computer Hodder p. 11

An easier way to see these stages in detail is the educational CPU model Little Man Computer (LMC), available at peterhigginson.co.uk/lmc. It uses assembly language — a simple instruction set, each instruction three letters, stored as a three-digit code in memory.

A worked cycle, bus by bus Hodder pp. 11–13

The textbook traces this program: LDA 4 · ADD 5 · STA 5 · HLT · DAT 23 · DAT 12. LDA 4 is stored as 504 at address 0. Note how all three buses are named at each stage — exactly what the syllabus asks for.

CycleFetchDecodeExecute
1 · LDA 4PC = 0, so address 0 is opened in RAM using the address bus and instruction 504 fetched on the data bus; the control bus sends a read signal. 5 → instruction register, 04 → address register. PC incremented to 1 via the ALU.The CU uses the control bus to co-ordinate. Instruction 5 decodes as "load into the accumulator"; address register 04 gives the address of the data.Address 4 opened on the address bus; control bus signals retrieval of data (23) on the data bus into the accumulator.
2 · ADD 5PC = 1. Address 1 opened, instruction 105 fetched, control bus sends read signal. 1 → IR, 05 → address register. PC incremented to 2.Instruction 1 decodes as "add to accumulator"; address register holds 5.Address 5 opened, data 12 fetched; accumulator (23) and fetched data (12) passed to the ALU; result 35 stored in the accumulator.

Common mistake Hodder p. 13

Assuming the program counter is updated after the execute stage. It is not. The PC is updated during or immediately after the fetch stage, so it points to the next instruction before the current one is even decoded or executed. This ensures the CPU always knows where to find the next instruction.

The carwash analogy Hodder p. 14

Pipelining enhances CPU performance by overlapping the execution of multiple instructions. Picture a carwash with four stages — initial wash, detailed cleaning, rinse, drying — each taking five minutes.

ApproachHow it worksTwo carsPer car
Non-pipelinedEach car completes all stages before the next begins. Once car A finishes the initial wash, that stage sits idle waiting for car A to finish everything.5 × 8 = 40 min20 min
PipelinedAs soon as car A finishes a stage, car B enters it. No stage sits idle.5 × 5 = 25 min12.5 min

The same applies to a CPU: we are limited by the speed of the hardware, and improving that is expensive. Being more efficient with what we have is more beneficial.

Design of a basic pipeline Hodder pp. 14–15

A pipelined processor has multiple stages between an input end and an output end. Each stage performs a specific operation, and the output of one stage becomes the input for the next. Intermediate outputs are held in interface registers (also called latches or buffers). All stages and interface registers are synchronized by a common clock.

In the CPU the cycle is divided into five stages:

  • Fetch — the instruction is retrieved from memory.
  • Decode — the instruction is interpreted to understand the required operation.
  • Execute — the operation is carried out.
  • Memory access — any necessary data is read from or written to memory.
  • Write back — the result is written back to the CPU register.

Performance is measured in cycles, not minutes. A well-optimized pipeline can achieve close to one instruction per cycle, maximizing performance by reducing idle times and ensuring continuous instruction processing.

The formula for pipeline questions

For n instructions through a k-stage pipeline:

without pipelining  =  k × n
with pipelining     =  k + (n − 1)

Read it off the diagram: the first instruction needs all k cycles, then every later instruction finishes just one cycle behind the one before it.

Independent and parallel execution Hodder pp. 15–16

  • Independent execution — each core has its own set of pipelines, so it can fetch, decode, execute and write back independently of the others. Even if one core is handling an intensive task, the others continue without waiting. Like multiple carwash bays: while Team 1 dries car A, Team 2 rinses car B.
  • Parallel execution — multiple cores work on different parts of a single large task. In a multi-threaded application, different threads are scheduled on different cores. Like several teams on one large car: Team 1 washes the exterior, Team 2 details the interior, Team 3 cleans the wheels and undercarriage.

Top tip — the assembly line Hodder p. 16

Pipelining is like a factory assembly line: each stage handles a different part of the process and, once finished, passes the work on and immediately starts a new task. Multiple instructions are processed simultaneously, just at different stages. In a multi-core architecture, imagine multiple assembly lines each running its own pipeline.

Internal storage — HDD and SSD Hodder pp. 16–17

HDDs are older technology but still common, especially in non-mobile devices, as they are relatively cheap for the storage they offer. They use a spinning magnetic disk to read and write data, suiting large volumes of data — media files, backups, documents — where speed is not critical.

SSDs have no moving parts. They use flash memory, offering high-speed access and durability, making them popular in laptops and tablets and ideal for operating systems, software and games.

M.2 and eMMC Hodder p. 17

  • M.2 SSD — a form factor that "looks like a stick of chewing gum": very small and thin, taking much less space than a standard SSD. M.2 NVMe SSDs are faster than 2.5" SATA SSDs and easier to install — slot into the motherboard, one screw.
  • eMMC (Embedded MultiMediaCard) — used in low-cost devices such as entry-level smartphones and budget laptops where the full benefits of an SSD are not essential. Also flash storage using NAND flash memory, soldered directly onto the motherboard. Capacity and speed do not match a standard SSD, but performance is adequate for basic computing and simple applications.

TypeCharacteristicsBest for
External HDD / SSDPerformance and comparison identical to the internal versions.SSD for quick transfers, backups and portability; HDD for extensive backups and large media where speed is less critical.
Optical discsCDs, DVDs, Blu-Rays. Low cost per disc; slower read/write. Prone to scratches if not stored correctly, and require an optical drive, which is becoming less common.Data archiving and playback.
Memory cardsCompact, using NAND flash. SD, microSD, CompactFlash. Durable — resistant to physical shock, extreme temperatures and water. Slower than SSDs but faster than optical discs.Expanding storage in mobile devices; photos and video in cameras.

What compression is and why we do it Hodder p. 19

Compression is the process of encoding information using fewer bits than the original representation. Making file sizes smaller has two main advantages: it takes less room on secondary storage, and it is faster to transfer across a network.

Lossless vs lossy Hodder p. 19

LosslessLossy
What happensData is compressed to a smaller size but can be restored to the original without any loss of information.Reduces files by permanently eliminating certain information — redundant or less critical data.
HowIdentifies and eliminates statistical redundancy within the data; the process can be reversed when needed.The compressed version is not identical to the original but is, ideally, indistinguishable to human senses.
Used forText files and databases, where a loss of information would be critical.Multimedia — images, audio and video — where some loss of quality is acceptable for significantly smaller files.

Run-length encoding (RLE) Hodder p. 20

RLE is an effective lossless technique for files containing many consecutive repeated characters. It looks for "runs" where a character repeats, then encodes each run as a pair: the repeating character and the number of repetitions.

RLE is straightforward to implement and very effective for data with many repetitions — simple graphics and certain text files. It was often used on fax machines sending text documents down a telephone line, because those contained a lot of white space, achieving compression ratios of up to 8:1. However, for data without many repeated characters, such as a portrait photograph, RLE may not be effective and may even increase the file size.

The textbook's worked example Hodder p. 20

AAAAABBBCCDAA  →  5 runs
AAAAA | BBB | CC | D | AA
encoded  →  5A3B2C1D2A

original   13 × 8 = 104 bits
compressed 10 × 8 =  80 bits
reduction  →  23%

Method for any RLE calculation

1 · Count the runs and write the encoded string.
2 · Characters × 8 for both strings.
3 · Reduction = (original − encoded) ÷ original × 100.

Always state the units and keep the original and encoded counts visible — the working carries marks even if the percentage slips.

Transform coding Hodder p. 21

Transform coding is a form of lossy compression used in JPEG image compression and MP3 audio compression. Using JPEG as the example:

  • Construct sub-images — the N × N image is sectioned into smaller n × n sub-images.
  • Forward transform — carried out on each sub-image. For JPEGs this is the DCT (discrete cosine transform), which takes the image data from the spatial domain (pixel values) to the frequency domain, breaking the sub-image into low- and high-frequency coefficients.
  • Quantizer — significantly reduces file size by simplifying those coefficients. It reduces the precision of high-frequency components (fine details) rather than low-frequency ones, because the human eye is less sensitive to high-frequency loss. The extent of quantization determines the compression level and final quality. This is the lossy step.
  • Symbol encoder — the quantized coefficients are further compressed using entropy coding, running three algorithms in this order: zigzag scan, run-length encoding, then Huffman coding.

Where the "lossy" mark is won

Students lose this mark by describing the four stages and stopping. The question asks why it is lossy — and the answer is the quantizer.

Quantization permanently discards precision from the high-frequency coefficients, so the original image can never be reconstructed exactly. The eye is less sensitive to that detail, which is why the loss is acceptable — but it is still a loss.

Ask who manages what. SaaS: the provider manages everything, you just use the app. PaaS: the provider manages the infrastructure, you manage the application. IaaS: the provider manages the physical hardware, you manage everything above it.
